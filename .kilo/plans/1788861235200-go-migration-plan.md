# План миграции Light Web Server с Python на Go

## Обзор
Переписать существующее Python-приложение Light Web Server на Go с сохранением всего функционала, включая:
- Сервер файлов с поддержкой Markdown
- Подсветка синтаксиса исходного кода
- Просмотр директорий
- Обработка LaTeX math (на стороне сервера)
- Отображение PDF документов

## Требования
- Полностью совместимый функционал с оригинальным приложением
- Единый бинарный файл без внешних зависимостей в runtime
- Базовая производительность (без специальных оптимизаций)
- Без дополнительных функций
- Серверная обработка LaTeX math

## Архитектура Go-приложения

### Основные компоненты
1. `main.go` - точка входа и HTTP сервер
2. `handler.go` - обработчик HTTP запросов
3. `renderer.go` - рендеринг Markdown, кода и математики
4. `directory.go` - генерация страниц просмотра директорий
5. `pdf.go` - обработка PDF файлов
6. `utils.go` - вспомогательные функции

### Внешние зависимости
- `github.com/gomarkdown/markdown` - для обработки Markdown
- `github.com/alecthomas/chroma` - для подсветки синтаксиса
- `github.com/go-latex/latex` или аналогичная библиотека - для обработки LaTeX
- Стандартная библиотека `net/http` - для HTTP сервера

## Этапы реализации

### 1. Подготовка структуры проекта
- Создание структуры каталогов
- Инициализация Go модуля
- Добавление необходимых зависимостей

### 2. Реализация базового HTTP сервера
- Обработка командной строки (host, port, directory)
- Базовая маршрутизация запросов
- Обслуживание статических файлов

### 3. Реализация просмотра директорий
- Генерация HTML списка файлов и подкаталогов
- Обработка навигации по каталогам
- Фильтрация скрытых файлов

### 4. Реализация рендеринга Markdown
- Парсинг и преобразование Markdown в HTML
- Поддержка таблиц, списков, кода с подсветкой
- Интеграция с механизмом подсветки синтаксиса

### 5. Реализация подсветки синтаксиса
- Определение языка по расширению файла
- Преобразование исходного кода в HTML с подсветкой
- Поддержка большинства языков из SOURCE_EXTS

### 6. Реализация обработки LaTeX math
- Парсинг математических выражений в документах
- Преобразование LaTeX в HTML/MathML на стороне сервера
- Защита кода от обработки как LaTeX

### 7. Реализация отображения PDF
- Генерация HTML страницы для просмотра PDF
- Интеграция с PDF.js для клиентского отображения
- Поддержка навигации по страницам

### 8. Реализация утилит и вспомогательных функций
- Обработка путей и безопасности
- Экранирование HTML
- MIME-типы для файлов

### 9. Компиляция в единый бинарный файл
- Настройка сборки с встраиванием всех зависимостей
- Проверка отсутствия внешних runtime зависимостей
- Оптимизация размера бинарного файла

### 10. Тестирование и отладка
- Проверка совместимости функционала с Python-версией
- Тестирование граничных случаев
- Отладка проблем с отображением контента
- Проверка корректной работы LaTeX math

## Критерии готовности
- [ ] Все HTML-страницы генерируются корректно
- [ ] Markdown файлы отображаются с подсветкой синтаксиса
- [ ] Исходный код отображается с подсветкой
- [ ] Директории отображаются в виде списка файлов
- [ ] PDF файлы отображаются во встроенном просмотрщике
- [ ] LaTeX math корректно обрабатывается на сервере
- [ ] Все поддерживаемые расширения файлов работают
- [ ] Скрытые файлы не отображаются в списке
- [ ] Защита от path traversal работает корректно
- [ ] Единый бинарный файл создается успешно
- [ ] Бинарный файл работает без дополнительных зависимостей
- [ ] Производительность приемлема для базового использования

## Риски и ограничения
- Сложность точного воспроизведения стилей HTML из Python-версии
- Возможные различия в обработке edge-case синтаксиса Markdown
- Ограничения библиотек для серверной обработки LaTeX
- Необходимость точной имитации поведения Python библиотек
